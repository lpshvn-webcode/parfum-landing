# KILLER PERFUME — локальный прототип

Актуальная версия — тёмная парфюмерная концепция для мужской аудитории: `noir.html`, `noir.css`, `noir.js`. Крупные брендовые флаконы, холодный и бордовый свет, готовые сеты одним нажатием и самостоятельный подбор из карточек. Главная страница открывает эту версию.

Указаны пять уникальных названий клиента; Pheramone повторяется в исходном списке и не считается шестым ароматом. Вариант «до 10 разных» допускает разные составы двух сетов, но для фактического выбора 10 уникальных ароматов нужен расширенный каталог. Это отмечено в предпросмотре. Происхождение парфюмерии (оригинальная или по мотивам) клиент пока не подтвердил; утверждений об оригинальности нет.

## Запуск

Нужен Node.js 20+. В каталоге репозитория выполните `npm run dev`. Сервер работает на порту 3000, альтернативный порт задаётся через `PORT`.

- `/?offer=10` — два независимо выбираемых сета, до 10 разных ароматов.
- `/?offer=5` — подарочный сет повторяет первый, до 5 разных ароматов.
- Панель внизу страницы переключает версии для просмотра.
- Выбор сохраняется отдельно для каждой версии в localStorage. Контакты не сохраняются.

## Tilda T123

`npm run build` создаёт:

- `dist/tilda-10.html` и `dist/tilda-5.html` — содержимое для T123 (без html/head/body).
- `dist/preview-10.html` и `dist/preview-5.html` — автономные страницы для локального просмотра.

Автономные `preview-*.html` включают фото и шрифты, их можно открыть без сервера. Экспорты `tilda-*.html` включают CSS и JavaScript, а фото и шрифты лежат в `dist/assets/`: это сохраняет размер HTML-блока небольшим. Для Tilda разместите эти ресурсы по публичному HTTPS-адресу и пересоберите с `ASSET_BASE=https://your-approved-host.example/perfume npm run build`, заменив адрес реальным. По умолчанию ссылки относительные и подходят для локального сервера, но не для чужого домена Tilda. Шрифтовый хост должен разрешать CORS.

Стили ограничены контейнером `#killer-perfume`. Размещайте только один вариант на одной странице Tilda: идентификаторы общие. Для сравнения нужны две страницы с разными адресами. Перед запуском уберите `.nk-review` из исходного HTML после выбора варианта и пересоберите. У Tilda контейнер T123 должен быть на всю ширину, без внешних отступов. Проверка в самой опубликованной странице Tilda остаётся отдельным этапом.

## Текущие допущения и материалы

- Конструктор моделирует пять флаконов по 10 мл на сет. Один аромат можно повторять. Подтвердить реальные фасовки с клиентом.
- Названия ароматов взяты из списка клиента. Описания характера и три сочетания — предварительные, требуют согласования; составы находятся в `noir.js`. Pheramone используется ровно с таким написанием, без выдуманного производителя.
- Новые изображения пяти флаконов сгенерированы для дизайн-концепции. Их сходство с упаковками производителя не удалось проверить: внешний доступ к parfbar.kz и сайту Clive Christian отклонён сетевым прокси (403 CONNECT). Это не фотографии реального товара. Pheramone — условный дизайн, поскольку производитель не указан. Исходные PNG сохранены в `/workspace/generated_images`. Текстовый знак KP — временная интерпретация логотипа.
- Шрифт Manrope с лицензией OFL взят из указанного заказчиком репозитория Küchen Technik. Лицензия хранится рядом с файлами шрифта.
- Реальные отзывы, фотографии и видео не получены; отзывы и показатели доверия не выдумывались. Соответствующий блок добавляется после получения материалов.
- Условия двух акций должны быть подтверждены перед рекламой соответствующей версии.

## Приём заявок

Сейчас форма проверяет данные и явно сообщает, что они не отправлены. Она не имитирует успешный заказ. Готовый HTML-блок сам по себе не подключает Tilda CRM.

Для подключения задайте `window.KILLER_PERFUME_CONFIG` до скрипта приложения:

```js
window.KILLER_PERFUME_CONFIG = {
  consentVersion: 'approved-policy-version',
  privacyText: 'Утверждённый текст политики с данными продавца…',
  async submitLead(payload) {
    // Реализовать адаптер к подтверждённому обработчику заявок.
    // Возвращать { ok: true } только после подтверждения приёма сервером.
    // При ошибке бросать исключение либо возвращать { ok: false }.
    // Не размещать секреты CRM/почты в клиентском коде.
    throw new Error('Lead receiver is not configured');
  }
};
```

Payload содержит имя, нормализованный телефон +7, согласие и его версию, вариант оффера, оба состава с объёмами, общую цену, UTM и рекламные идентификаторы из адреса страницы. При ошибке форма остаётся открытой с сохранёнными полями; повторная отправка во время запроса заблокирована. Нужен выбранный приёмник, серверная валидация, защита от спама и подтверждённая политика обработки данных до запуска. Никакие внешние подключения не создавались.

События DOM: `kp:selection_change`, `kp:checkout_open`, `kp:demo_completed`, `kp:lead_submitted`. Последнее происходит только после подтверждённого приёма. Контакты в события аналитики не передаются. Пиксели Meta/TikTok не установлены.

## Проверка

`npm test` использует установленный в облачной среде Playwright и Chromium. Сначала запустите `npm run dev` и выполните `npm run build`. Проверяется мобильная версия 390 px, узкий экран 320 px, десктоп, два оффера, готовые и ручные сеты, лимиты, повторы, сохранение, форма, ошибки приёма, автономный T123-экспорт. Скриншоты создаются в `artifacts/`.

Готовые WebP включены в репозиторий; исходные PNG для запуска и сборки не требуются. Публикация на Tilda выполняется отдельно после согласования.
